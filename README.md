# Sentinel · 屏幕哨兵 v2.4（iOS 注入插件）

圈一块屏幕区域 → OCR 认出关键字 → 横幅 + 震动报警。
配合 TrollFools 注入到任意 App 使用（未签名裸 dylib）。

## v2.4 改了什么（用户定调：精确优先）

| 改动 | 原因 |
|---|---|
| **删掉同义词功能**（面板区 + 配置 + 匹配分支全清） | 用户判断"完全没用"——同义词表要人工维护，鸡肋 |
| **删掉编辑距离容错**（`editDistance` / 滑窗比对整个移除） | 用户定调**宁漏不误**：OCR 认错一个字就不认，避免误报。留着 `matchOne` 只做精确包含 |
| **新增耗时日志** `timing(probe): 截屏 xx ms | 裁剪 xx ms | OCR+匹配 xx ms | 单轮合计 xx ms | 送检图 WxH 像素 | 文字 N 条` | 用户要"毫秒级"，先拿真机数据说话再调参，不拍脑袋 |
| 匹配链改为：归一化 → 精确包含 → 置信度阈值 | 与上面的取舍一致 |

> 关于"毫秒级"：Vision OCR 单次调用有固有开销（几十毫秒起）+ 截屏合成耗时，**单轮现实下限约 50~150ms**，"1 毫秒识别"在苹果 Vision 这条路上不存在。
> 能逼近的办法是**缩小监视区域**（用户目标位置基本固定）+ 提高扫描频率 + 砍掉"连中 2 轮"确认（省 0.5s）。
> 具体档位等真机 timing 数据回来再定。

## v2.3 修了什么（真机实测第二轮反馈）

| 问题 | 根因 | 修法 |
|---|---|---|
| 关键词/同义词/扫描间隔/报警冷却 **四行点了依旧没反应**（无卡片、无键盘） | v2.2 只修了"点击通路"，漏了第二层：`panelPrompt` 里那个窗口**建完从没显示过**（UIWindow 默认 `hidden=YES`），而且它不是 key window → `becomeFirstResponder` 失败 → 输入法也不弹 | `[w makeKeyAndVisible]` + 断言式日志（hidden/key/focus 三个状态都打出来）；点卡片外面取消从手势改 `UIControl`；输入卡片改成主线程同步弹出（可被自测断言） |
| 「入口挂到老贝贝设置页」这个模块看不懂 | 它是为"和另一个插件共存"预留的**占位开关，背后什么都没实现** | 连同"收到对端通知就降频 8 秒"整套共存逻辑一起**删除**（用户确认不需要） |
| 分不清注入的到底是不是新版 | — | 面板标题直接显示版本号：**屏幕哨兵 v2.3** |

## v2.2 修了什么（真机实测第一轮反馈）

| 问题 | 根因 | 修法 |
|---|---|---|
| 关键词/同义词/扫描间隔/报警冷却 四行点了没反应 | 这几行是 `UIView + UITapGestureRecognizer`，而同一面板里所有 `UIButton` 都正常 → 手势在非 key 悬浮窗里不触发 | 行的承载控件换成 `UIButton`（`mkRowField(value, w, action)`），遮罩也改 `UIControl` |
| 整屏监视后框缩小不了 | ①上面那行点不动 → 进不了框选；②四角手柄中心钉在框角上，整屏时一半悬在屏幕外 + 贴系统手势区；③整屏框铺满全屏，拖哪儿都算"移动框"且被边界卡死 | ①行可点；②手柄整体内收 `hs/2`；③保存的是整屏时，打开框选自动内缩一圈（0.08/0.10 边距） |
| 状态栏文字被截成一团、报警内容看不到 | ①状态行把整段识别原文拼进去了；②顶部横幅从 `y=0` 起步，整条被 iOS 系统状态栏压住 | ①状态行只显示「监视中 / 已暂停」，命中才缀「· 「关键词」」；②横幅从安全区下方开始；③**新增报警卡片**：完整显示命中关键词 + 识别到的原文 + 时间，8 秒自动收 / 可点「知道了」 |

## UI 形态

**视觉规格参考一款同类连点器的设置弹窗，逐项对齐**：
面板底 `#2C2C2E` / 圆角 18 / 宽 = 屏宽×0.66 / 标题左对齐 17 粗体 /
关闭按钮=白色实心圆+黑X / 字段标题 13px α0.62 / 输入框 `#3A3A3C` 圆角10 高44 /
分段控件底 `#1C1C1E` 选中=白药丸黑字 / 底部主按钮白底黑字、次按钮灰底白字 /
**无分割线，靠间距分区**。

结构（同一套界面语言）：
**模糊遮罩 → 面板卡片 → 标题栏(标题+渐变高光+关闭按钮) → 内容滚动区(分区：字段标题+控件行+分割线) → 底部按钮栏**

分区：状态 / 监视区域 / 关键词 / 节奏 / 报警方式
输入用面板内的**输入卡片**，全程**不使用 UIAlertController**（它和原生 Alert 都不会抢焦点）。

## 它做什么

1. 悬浮球（默认在屏幕**左侧**，可拖动）→ 点开面板
2. 「监视区域」那行点一下 → 重新框选（拖空白重画 / 拖四角缩放 / 拖框内移动；保存的是整屏时会自动内缩，方便拖小）
   「整屏监视」按钮 = 一键直接整屏（不弹框选）
3. 定时截屏 **只截这一块** → Vision OCR **只跑这一块**
4. 关键字命中（归一化 + 精确包含 + 置信度阈值）→ 顶部横幅 + **报警卡片** + 震动
5. 同一关键字冷却期内不重复报警

## 设计取舍（为什么这么做）

| 决定 | 原因 |
|---|---|
| OCR 只跑框选区域 | 省一个数量级 CPU；无关文字不进结果，误命中大降 |
| 匹配只有：归一化 / 精确包含 / 置信度阈值（v2.4 起） | 用户定调宁漏不误：宁可因 OCR 错字漏报，也不要误报 |
| 连中 2 轮才报警 + 冷却 | 单帧误报最常见的来源 |
| 报警用非阻塞横幅，不用 UIAlertController | Alert 会抢焦点，影响正在操作的 App |
| 声音只用 system sound，不建 AVAudioSession | 同进程里别的插件可能正在用音频会话（例如音量键监听） |
| 配置一律 `sentinel_` 前缀 | 不和别人的 NSUserDefaults 键打架 |

## 配置项（NSUserDefaults，全在 App 沙盒里）

| 键 | 默认 | 说明 |
|---|---|---|
| `sentinel_region` | 无 | `x,y,w,h`（归一化 0~1），由框选界面写入 |
| `sentinel_keywords` | `体力不足,无法操作` | 逗号分隔 |
| `sentinel_interval` | 2.0 | 空闲扫描间隔（秒） |
| `sentinel_cooldown` | 10.0 | 同一关键字报警冷却（秒） |
| `sentinel_vibrate` | YES | 震动报警开关 |
| `sentinel_sound` | NO | 声音报警开关（system sound 1007） |
| `sentinel_ball_pos` | 左侧 | 悬浮球位置 `x,y` |
| `sentinel_selftest` | NO | 自测模式（CI 用；不截屏，用现场渲染的假 HUD 图跑完整识别链） |

## 排错

- `idevicesyslog | grep Sentinel` → 实时日志
- 沙盒 `Documents/Sentinel.log` → 滚动日志（菜单里「📋 复制日志」可一键复制）
- 沙盒 `Documents/Sentinel_selftest.txt` → 自测报告
- 菜单里「🔍 试测一次」→ 立刻扫一轮，弹窗告诉你**它到底识别到了什么**（调关键词最快的手段）

## 构建

推 `main` 即触发 GitHub Actions（`macos-14` 云编译，无需 Mac）：

- `build.yml` → 产出 `Sentinel-dylib`（iphoneos / arm64）+ ldid 伪签名
- `simtest.yml` → 模拟器 e2e：编译 simulator 版 → 装 TestHost → `dlopen` 加载 → 跑内置自测 → 断言

模拟器里 arm64 的 `DYLD_INSERT_LIBRARIES` 不生效，所以 TestHost 在 `main.swift` 顶层用 `dlopen` 加载 dylib（等效 TrollFools 的注入时序）。
`-sentinel_selftest 1` 经 `NSArgumentDomain` 传进插件，触发自测。

## 安装（真机）

1. 下载 `Sentinel-dylib` artifact 解压得 `Sentinel.dylib`
2. 传到 iPhone，用 **TrollFools** 注入到目标 App
3. 冷启动 App → 左侧出现「哨」悬浮球 → 点它 → 圈定区域

> 需要 iOS 15+ 且设备已装 TrollStore / TrollFools。
> 插件不发任何网络请求，OCR 全部本地（Apple Vision）。
